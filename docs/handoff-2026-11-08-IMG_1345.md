## 実施済みの変更（2026-11-08、main にコミット・両公開先へデプロイ済み）
- `share-core.js measurementDefault`: 書き出しの既定は「割り当て済み÷音の打球 ≥ 0.8」のときだけ `confirmed`、それ以外は `audio`。`share-media.js` はこの関数で既定を決め、「映像で打点を選手に割り当てた打球（仮判定を含む）n／m 件」を注記する（コミット 864d27d、sw.js v46）。
- `share-media.js` 音モード: 映像の見直しで明示的に除外した音（`motion.events` の `ignored`）を数えない（コミット 0929f49。Codex #448 の P1 指摘）。
- テスト: `tests/test_share_core.js` 末尾に2件追加。全スイート通過。実機 Safari での再解析は未実施。
- 岩本さんの決定（2026-11-08）: 端末バックアップの書き出しは難しい。ストーリーズの打数は **総打数**。隣の組が疑われる区間は **打数は残し速度だけ集計から外す**。
- `share-media.js:84`: 音モードの表示を最長ラリーから総打数に変更（ラベル「打数」）。
- `video-quality.js review`: `overlap_suspect` を追加。孤立した短い間隔（<0.3秒で前後の間隔がその1.6倍超）か0.17秒未満の間隔を種に、前後2秒の打音の速度を集計から外す（打数は残す。手動 keep で戻せる。`overlapSuspect:false` で無効化）。連続して短い間隔（本当に速いラリー）は種にしない。切り出し版の再現では 0〜120秒は0件、120秒以降は158／312件が保留になり、保留分に105〜110km/hが集中（`local/.../scripts/overlap-proto.cjs`）。2組の周期がずれて全間隔が同じになる重なりは検出できない。
- `index.html` 速度の一覧: 除外理由を表示し、隣の組の疑いの件数を注記。sw.js v47。

## 残る修正の提案（優先順。Codex #448 の推奨順に揃えた）
1. **原因の確定**: 端末のバックアップで、記録の `analysisMode`・`audioHits`・`events` の `origin`、生成時の版を照合する。「映像から打点を出す」が有効だったなら、その設定が既定でオフであること、オンのときは書き出しの注記で明示することを確認する。
2. **音モードの表示定義をそろえる**: 総打数か最長ラリーか（`share-media.js:84`）、選択区間・母数・注記を一致させる。手動修正（player・type の上書き）を両モードでどう反映するかも統一する。
3. **隣の組の混入**（第1段は実装済み・上記）: 次は対象／背景／不明のラベル付き打音を作り、保留の取りこぼし（周期がそろった重なり）と過剰保留（本当に速いラリー）を測ってから自動分離を広げる。合否は「105〜110km/hが消える」ではなく「対象の打球を保持できる」こと。近側マイク補正（`motion-core.js:203-207`）は元の音番号と隣接性に依存するので、部分列化後は側と補正を再検証する。
4. **固定枠の追従と片側補完**: 直前の骨格の外接矩形＋余白で切り出し位置を更新し、背景人物への乗り移りと左右の入れ替わりを防ぐ。手動指定を優先する。
5. **平坦度の閾値**（0.17→0.15程度）は、混入区間・休止・声を含めて評価したうえで最後に。Python 整合は別途。
