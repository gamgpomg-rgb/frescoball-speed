## 2026-11-09 二重線の修正（Codex #451 の設計意見を反映）
- 症状: 紫の弧と実測の線が同じ飛行で20〜40px平行にずれて二重に見える（`evidence/story3-doubled-*.png`）。原因は弧の両端（打音時の手首）と実際の接触点のずれ＋実測側の重心誤差。
- 採用した方式（Codex 推奨 C の条件付き版）: 「1つの飛行の1つの時間帯は1本の線だけが描く」。同じ飛行に実測があれば、まず採用する観測を決め（最長の候補と同じ向き。逆向きの同程度の候補があれば曖昧として描かない）、強い観測だけに放物線（x等速・y重力固定）を当てはめる。採否は残差・各点誤差・継ぎ目（最初と最後の観測での誤差）で判定し、通らなければその飛行には描かない（手首どうしの弧へは戻さない）。描く範囲は観測で挟まれた欠測が基本で、弧の端が見えている手首に十分近いときだけ打点まで延ばす。表示用ブリッジのある時間帯も描かない。除外した音・隣の組の疑いの音は区切りとして残し、またいで1飛行にしない。弱い観測（動きだけの塊）の由来は候補→保存フレーム→track の点まで保持し、当てはめには使わない。観測が無い飛行だけ手首どうしの全区間の弧（`fullArcs` で無効化可）。
- 実フレーム45飛行（`local/.../scripts/arc-eval2.cjs`、骨格なしの枠アンカー）: 既定の採否で当てはめ19〜24本・観測なしの全区間弧2〜4本・描かない19〜22本。当てはめの残差中央値2〜3px、継ぎ目3px。Codex の暫定値（strict）だと5〜11本。
- 凡例: 「線：速度の色は映像から検出した球の候補・紫は見失った区間の推定（球速・打数には使いません）」。線種は岩本さんの指定で実線のまま（Codex は破線を推奨。未決）。
- 岩本さん決定（2026-11-09）: ①観測なしの全区間弧は既定で出す ②紫は実線のまま ③採否の既定は緩めのまま。いずれも現状どおりで変更なし。実機 Safari での見た目は未確認。sw.js v50。

## 残る修正の提案（優先順。Codex #448 の推奨順に揃えた）
1. **原因の確定**: 端末のバックアップで、記録の `analysisMode`・`audioHits`・`events` の `origin`、生成時の版を照合する。「映像から打点を出す」が有効だったなら、その設定が既定でオフであること、オンのときは書き出しの注記で明示することを確認する。
2. **音モードの表示定義をそろえる**: 総打数か最長ラリーか（`share-media.js:84`）、選択区間・母数・注記を一致させる。手動修正（player・type の上書き）を両モードでどう反映するかも統一する。
3. **隣の組の混入**（第1段は実装済み・上記）: 次は対象／背景／不明のラベル付き打音を作り、保留の取りこぼし（周期がそろった重なり）と過剰保留（本当に速いラリー）を測ってから自動分離を広げる。合否は「105〜110km/hが消える」ではなく「対象の打球を保持できる」こと。近側マイク補正（`motion-core.js:203-207`）は元の音番号と隣接性に依存するので、部分列化後は側と補正を再検証する。
4. **片側補完**（追従枠は実装済み・上記）: 実機で追従の効果を確認したうえで、`poseAudioEstimates` の「2人とも見えること」の要件を緩め、片側の腕の動きだけでも仮判定を付ける。背景人物への乗り移りと左右の入れ替わりが起きていないかを確認シートで見る。
5. **平坦度の閾値**（0.17→0.15程度）は、混入区間・休止・声を含めて評価したうえで最後に。Python 整合は別途。
