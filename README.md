# frescoball-speed

フレスコボールの7mラリーを、打音または240fps動画から計測するローカルPWAとPython解析ツールです。動画・音声・記録は端末内で処理し、標準では外部へ送信しません。

## スマホで動画を解析・保存する（2026-09-13更新）

既定の「シンプル」は動画の自動計測と、2人を選ぶ映像解析の2段階です。「詳細」へ切り替えると判定修正や細かい設定を開けます。「カメラ」は従来のライブ計測です。シンプルと詳細の切替で動画・選手指定・解析結果は失いません。解析中は左上に円形の進捗表示が追従し、完了・中止・失敗を区別します。進捗は処理の割合で、精度ではありません。

1. 小さな「選手間の距離・変更」表示から距離を7.0m以上、0.1m単位で指定し、動画を選ぶと自動で解析を始めます。まず音からの速報として動画・球速・左右の打数を表示します。
2. 必要なら「2人を選んでもっと詳しく」を開き、1人目と2人目の全身を囲んで自動解析します。完了した音声解析は再利用します。
3. 詳細解析の完了後も元の動画レイアウトで再生できます。骨格と球の軌跡は同時に表示します。個別の表示設定は詳細の折りたたみ内にあります。
4. 気になる判定は「詳細」モードで映像と再生位置を見ながら修正します。不明な音を落球として数えません。落球数は区切りと最後の空白から推定し、「落球数を修正する」で実際の回数へ変更できます。修正値は記録・出力へ保存し、推定値にも戻せます。
5. 「ラリーを保存する」でストーリーズ動画・画像を選びます。音からの速報と映像を使った推定を区別して保存できます。

解析後は選手の選び直しや範囲の変更を折りたたみます。細かい条件・バックアップ・手動追加は詳細欄にまとめ、普段は不要です。バックアップはブラウザの記録を消した場合や機種変更に備える控えであり、精度を上げる機能ではありません。

骨格付きの書き出しは解析済みの区間だけで使えます。元の画角の動画は全編も選択でき、ストーリーズは最大60秒です。ストーリーズには全体のラリーと2人の拡大映像を配置できます。リザルトカードの構成は変更していません。

解析と確認内容は端末の記録へ保存します。同じファイル名・サイズの元動画を選び直すと、保存していた解析も利用できます。

計測結果の直下にある「速度分布を見る」を開くと、左右別と全体合算の速度分布が表示されます。既定は閉じた状態です。距離を変更すると球速は自動で再計算されます。

### 気になる速度を除く

「飛び抜けた速度を自動で除く」は、前後の複数の打球と比較し、孤立した高速値を速度集計から除きます。20件以上の有効な速度がある場合は動画全体の分布も使い、上位の速度帯に裏付けがあるかを確認します。近い高速値が2件以上あれば孤立値としての除外を解除します。明示的な速度上限は別に適用します。105km/hなどの固定値を異常と決めつける方式ではありません。周囲の情報が不足する場合や連続した高速打球は自動除外しません。上限を指定したり、速い順の一覧から1件ずつ除いたり、元に戻したりできます。

除外は平均・最高速・分布・保存画像・動画の速度表示へ反映します。元の速度を保持し、履歴でも取り消せます。打数は変わりません。距離を変えた場合は速度を計算し直してから判定します。物理モデルと実測校正係数は変更していません。

### 実装範囲と検証

- 人物：MediaPipe Pose Landmarker Full（tasks-vision 0.10.32）。指定した各範囲内の骨格推定です。同じ範囲に別人が入る場合の人物同一性は保証しません。
- 球：赤色・フレーム差分・移動の連続性から抽出する実験的な候補です。球は30fps、骨格は15fpsで解析し、中間フレームは直前の骨格とその取得時刻を保持します。追跡は0.12秒以内で方向と速度が整合する欠測だけ補間します。補間点は破線とし、接触の自動確定の証拠には使いません。観測区間の外への外挿は表示しません。球専用の学習モデルではなく、背景に人が多い区間では誤候補が残ります。球と手首の反転照合による判定と、音に同期した腕の動きによる仮判定を区別します。仮判定も推定集計に含みますが、要確認として修正できます。
- アタック／ディフェンス：肩・腰を基準にした手首の動きと位置による画面上の推定です。利き手や体の奥行きが確定している分類ではありません。分類できた打球数を明示し、未分類を交互順だけで埋めません。詳細では手動修正できます。修正は端末内に保存し、共有学習は行いません。
- ラケット専用検出、腰の3D回転、実測初速、隣の組の完全自動除外、ライブカメラへの骨格表示は未実装です。対象打球の自動判定は実験的なロジックであり、精度保証ではありません。提供動画の180〜188秒の既存抽出データでは、14個の音候補のうち自動採用3件、要確認11件でした。これは採用数であり、正解との照合による精度ではありません。現在は腕の動きに明確な左右差がある場合に仮判定も行います。その追加分を含む実動画の正解率は未検証です。
- 7mのロープは基準長です。手前の地面のロープを、そのまま空中の球の縮尺に使いません。精密化には同期した複数方向の撮影・カメラ校正・スピードガンとの比較が必要です。TOP/CLASSICの公式計測・採点への適合は未検証です。
- 計算・除外取消・記録復元・対象選択・書き出しの区間と描画を回帰テストで検証。提供動画と抽出済み骨格を使い、アプリと共通の描画処理から保存サンプルを生成して確認しています。サンプルのMP4エンコードはローカルのffmpegです。ブラウザのMediaRecorderによる録画と、スマホの写真アプリへの保存は実機未検証です。
- 通常の処理で映像の外部送信はありません。初回の骨格モデル・実行コードの取得にはインターネット接続が必要です。

参考：[MediaPipe公式Web実装](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)、[McByte++](https://github.com/tstanczyk95/McBytePlusPlus)、[tennis-cv](https://github.com/collidingScopes/tennis-cv)。参考実装の精度をこのアプリの実測値として扱っていません。

## 最短の使い方（HTTPS）

初回だけ、Macにローカル開発用の認証局を用意します。これはこのアプリ専用の設定変更ではなく、`mkcert` の標準的なローカルHTTPS設定です。

```bash
brew install mkcert
mkcert -install
```

以後の起動は1コマンドです。

```bash
./scripts/serve.sh
```

表示された `https://127.0.0.1:8443/` をMacのブラウザで開きます。HTTPへのフォールバックはしないため、カメラ・マイクの安全な利用条件を崩しません。

### iPhone / iPadで使う

1. Macと端末を同じ信頼できるWi-Fiへ接続します。
2. Macで `./scripts/serve.sh --lan` を実行し、表示された `https://<MacのLAN IP>:8443/` を端末で開きます。
3. 初回のみ、`mkcert -CAROOT` にある **`rootCA.pem` だけ** を端末へ安全に転送してプロファイルをインストールし、「設定 > 一般 > 情報 > 証明書信頼設定」で信頼を有効にします。秘密鍵は絶対に転送しません。
4. Safariの共有メニューから「ホーム画面に追加」を選ぶとPWAとして起動できます。

不特定多数がいるネットワーク、他人の認証局、公開インターネットへの公開では使わないでください。`--lan` は終了時にCtrl-Cで停止します。

## 計測の仕様

`measurement-spec.json` がWebとPythonの唯一の計算正本です。

- 初速換算は、ボール寸法・質量・抗力からの理論モデルを空欄時の既定にします（7mで平均速の約`1.07008`倍）。実測校正値はスピードガン等の根拠がある場合だけ、設定の「実測校正係数」に入力します。
- 片側マイクでは、最初の打音がマイクの近側か遠側かを明示します。近側→遠側の観測間隔からは音の伝搬時間を引き、遠側→近側では足します。
- ライブ・動画解析とも、補正後の飛行時間が0.20〜0.90秒、かつ初速が設定上限（既定110km/h）以内のものだけ速度集計に採用します。除外された打音は打数には残り、画面に理由が出ます。
- マイク開始後0.75秒と動画先頭0.50秒は、入力・フィルタの初期ノイズを学習する安定化期間です。この間の音は打数にも速度にも入りません。安定化後の実測90km/h超は、設定上限以内なら通常どおり集計します。

計算仕様を更新したら次を実行します。

```bash
python3 scripts/sync_measurement_spec.py
./tests/run_tests.sh
```

## PWAの機能

- ライブ打音計測: マイク入力は解析専用の無音経路に接続され、スピーカーには出ません。効果音・BGMのみ通常どおり再生されます。新しく開いた画面は必ず0から始まり、保存済みの集計は「前回の集計を再開」を押したときだけ復元します。
- 動画解析: 新しい動画を選んだ時点で前の速度・打数表示を0へ戻し、古い解析処理が後から新しい結果を上書きしないようにします。音声検出後に「映像で精査」をすると、打者の左右判定・隣の組の除外を反映して同じ記録を更新します。
- 保存: 設定とライブ集計はブラウザのローカルストレージ、動画解析記録はIndexedDBに保存します。記録には選手、設定、計算仕様、映像精査バージョンを保持します。旧記録は開いたときに互換形式へ移行します。
- 出力: 動画解析ダッシュボードからJSON（完全な記録）とCSV（打音ごとの時刻・選手・初速）を端末へ出力できます。

通常のライブ計測は外部通信なしで動きます。大容量MP4の音声トラック解析では初回に`mp4box.js`、外部AI雑音除外をオンにした場合は初回にモデルを取得します。PWAの基本画面と計算仕様はサービスワーカーでキャッシュします。

### シンプル解析の負荷軽減（2026-09-13）

速度・打数は音声解析後に表示し、2人を選ぶ追加解析が完了すると骨格とボールの軌跡が加わります。読み取れない区間の軌跡は表示しません。
シンプルでは骨格を通常5回/秒、打球音の前後0.18秒は従来の15回/秒で読み取ります。詳細は15回/秒を維持します。ボール探索は両モードとも30回/秒です。
探索範囲と身体の除外点を画素ごとに再計算せず、フレームごとに一度計算するよう変更しました。選手用の描画キャンバスも使い回します。

既存動画180〜188秒の保存データで、骨格推論予定数は240→170回（約29％減）、打球候補14時点を両選手で比較した28件のフォーム推定結果は一致しました。これは保存済み骨格を使った比較で、正解率の検証ではありません。
ローカルNode canvasで同じ実画像を10回探索する部分測定は約2,483→41ms、候補25個は一致しました。この数値は画素探索のみで、ブラウザ・スマホの解析全体の時間や倍率ではありません。映像の読み出しと骨格モデルの実行時間は別途かかります。

### ペアの役割と軌跡の補助表示（2026-09-13）

アタック／ディフェンスは、手首と同じ側の肩の位置を使い、体の外側への打ち込みと、正面・体を横切る打ち方を区別します。2人の役割は相補的とし、ラリー内の姿勢の流れから役割の継続・交代を推定します。単発の姿勢の揺れでは切り替わりにくく、手動修正を優先します。未確認の打球や2秒を超える区切りをまたいで役割を引き継ぎません。これは2D骨格による推定で、利き手やラケット接触を直接認識した結果ではありません。

画面と保存動画では、独立して追跡できた前後の軌跡の間（最大0.24秒）を方向・速度が一致する場合だけ破線で補います。打球付近では、判定済み打者の見える手首と進行方向が一致する場合に最大0.18秒の補助線を表示します。いずれも表示専用で、速度・打球判定には使いません。長い空白や情報のない区間は残ります。

保存済み180〜188秒のデータで表示可能フレームは220/240→225/240。追加箇所の切り出し画像を確認しましたが、接触付近の位置ずれは残り、実測軌跡ではありません。判定済み9打中、役割を推定できた8打はアタック4・ディフェンス4となりました。件数は正解率を表しません。役割交代・ノイズ耐性・手動修正優先・左右反転・短い補助線と判定根拠の分離を回帰テストしています。

### 速度定義の統一・途中再開・屋外UX（2026-09-13）

速報／対象2人の追加解析／保存動画を、measurement-spec.jsonの同じ物理モデルによる「推定初速」に統一しました。区間平均は内部値として保持します。速度の品質条件に合わない打球も、接触として採用済みなら打数には残します。追加解析で打球候補・打者・時間の組み合わせが変わると数字は変わります。近接マイクで音源側を確定できない手動打球などは、補正速度を捏造せず保留します。選手間距離は打点間距離とは異なり、レーダーの実測値との一致を保証しません。

ラリーの区切り、動画末尾の空白、手動確認した落球数を別フィールドで保存します。落球の接地を認識しているわけではありません。両手が近接して動く打球は、体の外ならアタック、正面ならディフェンスとして扱います。正解付き動画作成とフォーム改善助言は保留です。

途中経過はIndexedDBの専用DBへ90フレームごと（映像3秒分）と中断時に分割保存します。同じ端末・ブラウザで同じ動画を再選択すると、前回の選手範囲を復元して続きから解析できます。動画の名前／サイズ／更新時刻／解像度／長さ、選手範囲、モード、解析区間、打球候補が変わると別の解析として扱います。元動画は保存しないため再選択が必要です。ブラウザデータの削除や保存容量不足では再開できない場合があり、画面に通知します。詳細内に途中保存を削除する操作があります。

進捗に「速度・打数は確認できます」を表示し、処理速度を測れた段階で残り時間の目安を追加。対応環境では画面消灯を抑制します。詳細モードに「今の場面の判定を直す」を追加し、補助文字のコントラスト、距離変更などのタップ範囲、フォーカス表示を改善しました。

検証：通常の回帰テストに加え、fake-indexeddbで中断→新しい実行環境→選手範囲復元→途中再開、重複なし、モデル実行回数減少、別動画／別モードの分離を確認。以下で再実行できます（fake-indexeddbはテスト用で本番依存に含めません）。

```bash
FRESCO_TEST_IDB_MODULE=/tmp/frescoball-checkpoint-tests/node_modules/fake-indexeddb ./tests/run_tests.sh
```

### ピンク球の追尾（2026-09-13）

球速は打球音の間隔と選手間距離からの推定初速を維持し、画素の移動量からkm/hを算出しません。追尾は赤・ピンク色、前フレームとの差、時間をかけて更新する背景との差、小さな塊、移動の連続性を組み合わせます。薄い色や短いブレの緩和は予測位置の近く、かつ選手の枠外に限定します。見つからない球を観測点として作りません。短い表示補間は引き続き破線です。

実動画比較・処理負荷・制限は `tests/ball-detector-validation.md`。全区間の正解率向上を実証したものではありません。新しい追尾は動画の再解析で適用されます。途中保存はアルゴリズムのバージョンごとに分離します。

### 打数の基準と左右・打ち方の内訳（2026-09-13）

追加解析で腕・球の接触を確認できなかった音を集計から落とす問題を修正。`FrescoMotion.countedEvents` は保存された音の時刻列を基準にし、明示的な対象外指定だけを除外し、手動追加を含めます。視覚の未確認状態は元イベントに残し、集計用には左右の交互推定を追加します。球速の物理モデルは変更していません。

再生・保存動画の左右には総打数とA/D内訳を表示。A/Dは既存の役割推定を音基準の打球列に適用し、前後の手掛かりから補います。一つのラリー全体に手掛かりがなければ分類を作らず、総打数にだけ含めます。左右の割当も推定です。

落球の推定は音基準の打球間隔で計算するため、骨格の検出漏れによる人工的な区切りを作りません。音の空白は落球そのものの証拠ではなく、休憩・回収・検出漏れを含みます。実測値での修正を主画面の「落球数を実測値に合わせる」から行えます。周囲の打音や音の検出漏れがあるため、自動計数の完全一致は保証できません。

検証: `tests/test_audio_count_authority.js` と主画面の結合テストで、30打中26打の映像判定が欠けても30打・1ラリーを保持。明示除外、手動追加、前後のA/D補完、全体が不明な場合に分類を捏造しないこと、保存動画の音基準集計を確認。実際の落球22回という表示の正解値は未確定。

### シンプル表示のA/D補完（2026-09-13）

シンプルモードは `FrescoShots.simpleRoles` で表示用の役割を補い、左右それぞれA+Dが総打数に一致するようにします。既存の打ち方・手動修正を優先し、同一ラリーの前後の役割を参照します。手掛かりがないときは直前の役割を維持し、動画冒頭にも手掛かりがなければ最初の打者をアタック、相手をディフェンスとして仮置きします。これは観測結果ではなく表示用の予測です。「推定」を表示し、詳細の視覚的な判定データ、打数、速度を変更しません。

音だけの簡易計測でも補完します。シンプルモードの保存動画にも適用し、詳細モードでは根拠のない初期役割を追加しません。テストは14打ずつの無判定、前後の役割・手動修正、途中の交代、モード切替、左右入替、巻き戻しを確認。画面上の数字の整合性の検証であり、実際の打ち方の正解率を保証するものではありません。
